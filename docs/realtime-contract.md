# M3-D realtime contract and implementation plan

Status: opt-in implementation supplied, with synthetic offline validation; no live realtime acceptance is claimed. No live subscribe/unsubscribe authorization or captured realtime payload exists yet.

Pinned [official middleware TS-25.04.2.6](https://github.com/truenas/middleware/tree/244b717370fe35fb9eefc3096acfbc25f12b57b6) supplies the following implementation evidence. Paths are relative to src/middlewared/middlewared/. The [published realtime event reference](https://api.truenas.com/v25.04/api_events_reporting.realtime.html) alone does not fully specify CPU/network wire fields, so the tagged producer is the baseline:

- plugins/reporting/events.py: interval >=2; ADDED fields; REPORTING_READ role; failed_to_connect=true may be the entire fields object.
- realtime_reporting/cpu.py: cpu/cpuN objects, usage percent.
- realtime_reporting/ifstat.py: link_state UP/DOWN; speed in Mbps; received_bytes_rate/sent_bytes_rate already bytes/s. Down links may include generated zero rates; omit down-link rate/speed samples. Missing values never become zeros. Upstream missing-dimension defaults can already be zero; the exporter cannot reconstruct provenance lost upstream.
- realtime_reporting/memory.py: physical_memory_total/available and arc_size are bytes. Physical memory and ARC validate independently despite sharing a source object. No duplicate total-memory metric: system.info remains canonical for truenas_memory_total_bytes.
- realtime_reporting/arcstat.py: selected demand data/metadata hit percentages convert once to ratios; ARC size is required, hit ratios optional.
- service/core_service.py: core.subscribe params=[full_event_name] returns a UUID string; core.unsubscribe params=[the connection-owned identifier] returns null.
- api/base/server/ws_handler/rpc.py and common/event_source/manager.py: collection_update params.collection is the full dynamic subscription name, msg=added, fields=payload; notify_unsubscribed carries collection/error. Events may arrive before acknowledgement because the source starts while subscribe is executing.

Use a separate per-target authenticated/version-checked socket so a denied or failed subscription does not interrupt ordinary polling. Each socket still has verified TLS and bounded writes/reads, cancellation and reconnect/backoff. Only the exact reporting.realtime:{"interval":N} collection is accepted. Keep at most one pre-ack event and only typed latest snapshots after acknowledgement; no unbounded event queue. Subscription identifiers stay connection-owned and never appear in logs/labels. Best-effort cancellation cleanup has a one-second total budget for unsubscribe/ack/close; disconnect also removes server-owned subscriptions.

TRUENAS_REALTIME_ENABLED defaults false and requires TRUENAS_SYSTEM_ENABLED=true. Interval defaults 2 seconds (2..300), realtime TTL defaults three intervals (greater than interval, maximum 86400). Enabled realtime requires fresh CPU/memory/network/ARC groups in addition to pools/system for readiness. Each group has its own typed snapshot, timestamps, attempts/errors and TTL; partial valid groups do not refresh invalid ones. Backend failure marks all groups unavailable while retaining last good data until expiry. Stream silence triggers reconnect even when pongs continue. Empty interface sets are valid snapshots and remove deleted interfaces.

Bound text frames to 256 KiB, fields to 128 KiB, CPU entries to aggregate plus 256 cores and interfaces to 128. Validate names and numeric ranges before storing vectors. Parse only selected fields; ignore disk and hardware metadata. Rates are gauges, not counters. Synthetic mode never opens sockets and remains explicitly labeled. Add a fixed-output one-shot check-realtime for future operator-authorized acceptance.

Verify schemas/conversions, partial failures, exact expiry/recovery, ownership/pre-ack buffering, silence, cancellation cleanup, reconnect/resubscribe and unchanged polling with unit/loopback/process/container checks. Live fixtures, role verification and enabled-mode resource budgets remain separate acceptance work. Complete the user's milestone commit workflow after passing required checks.

## Connection and failure policy

Polling and realtime each have one verified authenticated socket per target. The polling socket remains the owner of normal system/pool compatibility and snapshots; the realtime socket performs its own system.info gate before subscribing. A known unsupported version observed by the realtime gate also revokes target compatibility and wakes the polling connection to recheck. Subscription permission failures do not revoke an otherwise valid polling connection. A successful realtime subscription cannot reopen the polling compatibility gate.

Realtime connection/malformed-control/schema failures retry with capped exponential backoff and jitter, resetting only after 120 seconds of an acknowledged subscription. A stream timeout/drop or remote notify_unsubscribed marks all realtime groups failed but retains last good snapshots only through their own TTL. Transport/permission retry failures retain the bounded grace; unverifiable/unsupported reconnect schemas fail closed for realtime. A fresh group can still emit while a sibling expires. Liveness remains independent; readiness requires every configured target's required snapshots, including all four realtime groups when enabled.

ACKs are limited to 4 KiB. The application rejects realtime text over 256 KiB within the shared transport's 1 MiB maximum; fields are limited to 128 KiB. CPU/interface objects use bounded visitors and reject duplicates before constructing stored vectors. Events before ACK overwrite one pending typed frame, retaining its original monotonic receipt time. Afterwards frames publish directly into bounded latest-snapshot state; there is no growing message queue or task per event. Scrape encoding remains separately admission-bounded.

The source emits the full dynamic collection name, including JSON parameters; this requires decoding escaped strings correctly. Unrelated notifications/collection names never refresh stream/group freshness. A missing/malformed group is a failed attempt for that group only, and never inserts zeros. The source itself may already substitute zero for missing Netdata dimensions; exported zero cannot distinguish that from a genuinely zero source measurement. Captured/UI comparison is still necessary to evaluate that limitation.

## One-shot preflight

`truenas-exporter check-realtime` requires exactly one non-mock target and both TRUENAS_SYSTEM_ENABLED=true and TRUENAS_REALTIME_ENABLED=true. It authenticates, reads system.info, subscribes to the exact configured reporting.realtime name, waits for fresh validated CPU/memory/network/ARC groups, then unsubscribes its owned ID and closes. It sends no pool query or arbitrary event/method. Connect/auth/version/subscribe share one API-timeout budget; observation is bounded by API timeout plus two intervals, also subject to the stream-silence TTL. Cleanup gets at most min(API timeout, one second). Success/failure output contains no returned identity, payload or subscription ID. Even RUST_LOG=trace does not enable dependency logging in this command.

A future live preflight needs explicit authorization for auth.login_ex, system.info, core.subscribe for this exact event, and core.unsubscribe for the connection-owned ID, from the chosen host/container. Existing pool/system approvals do not authorize these event methods. No live invocation was performed during implementation. Full sanitized realtime captures, actual REPORTING_READ authorization, down/missing-link appliance cases and runtime resource measurements remain pending.
